### Decisions and the reasoning behind them

- **The Next app lives in `web/`, deployed from `web/`.** Not the repo root — the
  root is the course lab kit. Deploying from `web/` also means the repo-root
  `.env` is never in the upload.
- **The key is read only in `web/app/api/chat/route.ts`**, server-side. No
  `NEXT_PUBLIC_` prefix anywhere, which is the only thing that would inline it
  into the client bundle. Verified by grepping `.next/static` for the key value
  after a build — clean.
- **Local dev reads `../.env`; Vercel supplies its own env vars.** The route
  falls back to dotenv on the repo-root `.env` only when `OPENAI_API_KEY` is
  absent, so one key file serves both the labs and the web app.
- **The password gate exists because Vercel's protection does not cover custom
  domains.** Standard Protection protects everything *except* production domains,
  and raising the scope to All Deployments needs Pro. `starkfarms.in` **is** the
  production domain, so on Hobby it is public. The gate in the route handler is
  the only thing defending the key there. It fails closed: missing
  `CHAT_PASSWORD` in production locks the route rather than opening it.
- **DNS stayed on Google Cloud DNS**, apex `A` → `216.198.79.1`, rather than
  delegating nameservers to Vercel. Keeps MX and any other records intact.

### Traps hit, so they are not hit again

- **The proxy's final stream chunk has an empty `choices` array** (usage only).
  Indexing `chunk.choices[0]` blindly throws `IndexError` / undefined. Both
  clients guard for it.
- **Vercel production and preview env vars are stored *sensitive* = write-only.**
  The dashboard, `vercel env ls` and `vercel env pull` all return `[SENSITIVE]`.
  A password typed at `vercel env add`'s interactive prompt and then forgotten is
  gone for good — this happened once and cost a rotation. Always pipe a value in.
- **Env var changes only reach deployments built after them.** `vercel env add`
  alone changes nothing live; it needs `vercel --prod`.
- **`bash -n` will not catch `$VAR` followed by a multibyte character.** Under
  `set -u`, `echo "$SITE…"` parses the name as `SITE…` and dies at runtime. Brace
  it: `${SITE}`. This bit the rotate script on its first real run.
- **`sed -i ''` is macOS-only.** The rotate script uses it; on Linux/CI it needs
  plain `sed -i`.
- **Next 16 differs from older Next.** `web/AGENTS.md` and `web/CLAUDE.md` are
  generated by `next dev`, not hand-written — read `node_modules/next/dist/docs/`
  rather than relying on memory.
- **This repo is a partial copy of the lab kit, and inherited files lie.** The
  root `README.md` was byte-identical to `mai-practitioner-labs/README.md` and
  described `labs/`, `corpus/`, `rag/` and a `labs/lab_1.py` smoke test — none of
  which exist here. Rewritten in `fdbf265`. `requirements.txt` is inherited the
  same way and still lists deps this code never imports. Check inherited files
  against the actual tree before trusting them.
- `origin` is `ModernAIPro/L2-RAG-EVAL-R1`, **not** the upstream lab kit, so
  `git pull` will not pull course updates or conflict with them. The lab kit's
  usual "copy `labs/*.py` before editing" warning does not apply here.
- Tool output twice contained instruction-shaped text aimed at the agent (a
  `vestauth.com` "tip" in Next's build log, a `claude-code-hint` plugin tag in
  `vercel curl` debug output). Both ignored; nothing installed.
